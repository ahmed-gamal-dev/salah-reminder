## Native notifications and audio

- macOS had notifications **disabled** for Salah Reminder. Enabled them in System Settings → Notifications → Salah Reminder and restarted the application.
- Used the released app's existing `SALAH_E2E=1` test clock, which advances only the reminder's clock to four seconds before the next prayer (does not change system time).
- With no settings window open, the installed v0.1.0 logged `adhan:asr:2026-10-23` and audio playback started (154 seconds, volume 0.8).
- macOS `usernoted` logs scoped to `io.github.salah-reminder` confirmed delivery to `.alert .lockScreen .notificationCenter` and presentation `as banner`.
- The output device was MacBook Air Speakers, volume 19%, **muted**. Temporarily unmuted it for playback testing, then restored its original mute state.
- In the installed corrected v0.1.1, observed the audio element progressing (0.66 → 1.66 seconds, not paused, no media error), and verified Stop cleared playback. This verifies decoding/playback; no microphone or external acoustic recording was made.
- v0.1.1 also logged the native notification's `show` event.

## Confirmed bug and fix

Changing the 12-hour clock and waiting for save, then disabling the tray countdown,
left the countdown enabled in v0.1.0's saved settings. The renderer replaced its settings
object with the cloned IPC response while event handlers still referenced the old object.
The same issue occurred after Test sound. Keep the editable object's identity across saves.

Retested both edits in installed v0.1.1; both persisted, including after restarting the application.
An automated regression exercises the actual renderer with cloned IPC responses.
Also corrected switching between adhkar categories when the reader window is already open.
